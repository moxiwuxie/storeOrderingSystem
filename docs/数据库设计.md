## 表关系

```
users ──1:N── cart_items ──N:1── products ──1:N── product_specs
  │                                │
  └──1:N── orders ──1:N── order_items

```

## 1. users 用户表

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK | 用户 ID |
| openid | VARCHAR(64) UNIQUE | 微信 openid（小程序端）|
| alipay_user_id | VARCHAR(64) UNIQUE | 支付宝 user_id |
| device_id | VARCHAR(64) UNIQUE | H5 端设备标识，用于浏览器 / 支付宝内免注册识别同一顾客 |
| nickname | VARCHAR(64) | 昵称 |
| avatar | VARCHAR(512) | 头像 |
| phone | VARCHAR(20) | 手机号 |
| status | TINYINT(1) | 1 正常 / 0 禁用 |
| created_at / updated_at | DATETIME | 时间戳 |

一个用户可以同时绑定微信与支付宝身份（两字段均可为空，登录时按渠道写入）。

多端身份识别：

- **小程序**：`openid` 唯一标识，`wx.login` 静默登录。
- **H5（浏览器 / 支付宝内）**：无法静默拿微信身份，故以 `device_id`（前端生成并持久化于 `localStorage`）标识设备；若在支付宝内打开则补充 `alipay_user_id`，若用户填写手机号则用 `phone` 关联，从而实现跨设备找回同一账号。
- 三个字段均为可空唯一索引，互不冲突。

> 注意：SQLite 仅支持 `INTEGER PRIMARY KEY` 自增，而 MySQL 使用 `BIGINT`。ORM 中通过 `BigIntType = BigInteger().with_variant(Integer, "sqlite")` 统一两种方言，保证开发（SQLite）与生产（MySQL）建表结构一致且主键可自增。

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK | |
| product_id | BIGINT FK → products.id | 级联删除 |
| name | VARCHAR(64) | 规格名，如「大杯 少冰」|
| price | DECIMAL(10,2) | 该规格售价 |

## 6. cart_items 购物车表

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK | |
| user_id | BIGINT FK → users.id | 级联删除 |
| product_id | BIGINT FK → products.id | |

## 订单状态流转

```
待支付(0) ──支付成功──▶ 已支付(1) ──商家核销──▶ 已完成(2)
    │
    └──用户取消 / 商家关闭──▶ 已取消(3)   （取消时回滚库存）
```

## 库存一致性策略

- **加购校验**：加入购物车、修改数量时即校验剩余库存，超出直接提示。
- **下单扣减**：创建订单在一个数据库事务内逐项校验库存并扣减，任一项不足则整体回滚并返回「XX 库存不足」。
- **取消回滚**：取消待支付订单时按明细把库存加回对应商品或规格。
- **并发说明**：当前实现基于单事务校验 + 扣减，满足单门店并发量；若需强一致高并发，可在 `products` / `product_specs` 行上加 `SELECT ... FOR UPDATE` 悲观锁或改用 Redis 预扣减。
